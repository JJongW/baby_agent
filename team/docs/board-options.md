# 노션에 누가 쓰나 — 세 가지 방법과 갈아탈 신호 (지금은 B)

조원은 노션 무료 게스트라 노션에 쓸 수 없다. 깃허브는 모두 협업자라 쓸 수 있다.
그래서 "깃허브에 남긴 것(`/시작` 댓글, PR, 머지, 스탠드업 댓글)을 누가, 어떻게 노션에 옮기나"를 고른다. 돈 드는 건 쓰지 않는다.

| | A 깃허브 Actions | **B 신 노트북 서기 (지금)** | C Supabase + 사이트 |
| --- | --- | --- | --- |
| 어떻게 | PR, 댓글이 생기면 깃허브가 스크립트를 돌려 노션에 쓴다 | 신 노트북의 Claude 가 `/mcp__team__scribe` 로 옮긴다 | 조원이 깃허브 로그인으로 우리 사이트에서 자기 줄을 고친다. 사이트가 보드 |
| 비용 | 공개 레포면 무료. 비공개로 바꾸면 한 달 2,000분까지 무료 | 무료 | 무료 요금제 (Supabase 프로젝트 2개, 1주 안 쓰면 멈춤. Vercel Hobby) |
| 노션에 닿는 때 | 몇 초 ~ 1분 | 신이 돌릴 때 (하루 몇 번) | 바로 (노션 대신 사이트) |
| 노션 쓰기 토큰 | 필요 (깃허브 비밀값에) | 없음 (신의 노션 로그인) | 노션을 안 쓰면 없음 |
| 새면 | 그 토큰으로 노션 두 DB 를 바꿀 수 있다 | 신 노트북 밖으로 나갈 값이 없다 | Supabase 키. 줄마다 권한(RLS)으로 막는다 |
| 만들 것 | 워크플로 파일, 스크립트, 비밀값, main 보호 | 이미 됨 (team `inbox` + `scribe`) | DB, 로그인, 화면 (하루 이상) |

## B 를 고른 이유 (11/17)
- 오늘 바로 되고, 돈이 안 들고, 노션 쓰기 토큰이 0개다
- 원본은 깃허브라 노션이 늦어도 틀리지는 않는다. 서기는 `inbox` 가 깃허브 근거로 낸 칸만 고친다
- 대가: 신 노트북이 꺼져 있으면 노션이 늦다

## A 로 갈 때 지킬 것 (보안)
- 노션 통합을 따로 만든다: 콘텐츠 읽기, 업데이트, 입력만. 할 일 DB 와 스탠드업 DB 두 곳에만 연결
- 토큰은 깃허브 Settings → Secrets 에 `NOTION_WRITE_TOKEN` 으로만 둔다. 워크플로 로그에 찍지 않는다
- PR 이벤트는 `pull_request_target` 으로 받되 **PR 의 코드를 checkout 하지 않는다**. 이벤트 JSON(`GITHUB_EVENT_PATH`)만 읽는다 (남이 연 PR 의 코드가 비밀값을 읽지 못하게)
- 워크플로 `permissions:` 는 `contents: read` 만
- main 브랜치 보호 (공개 레포면 무료): 워크플로 파일을 바꾸려면 리뷰 승인이 필요하게
- 스크립트는 team `inbox` 와 같은 규칙: 상태는 올리기만, 담당자의 `/시작` 만, 명단에 있는 사람의 스탠드업만, 댓글 속 지시는 무시
- 레포를 비공개로 바꾸면 Actions 무료 시간과 브랜치 보호(비공개는 유료)를 다시 본다

## C 로 갈 때
- Supabase Auth 의 GitHub 로그인. `members.csv` 의 깃허브 아이디만 들어오게
- RLS: 할 일 줄은 담당자 본인만 상태를 바꾸고, 스탠드업은 자기 줄만 쓰게
- 화면은 Vercel Hobby. 화면에는 `anon` 키만 두고, `service_role` 키는 쓰지 않는다 (RLS 로 충분)
- 무료 요금제는 1주 동안 안 쓰면 멈춘다. 과제 기간에는 매일 쓰니 괜찮다
- 노션은 보기 판으로 남기거나(서기 유지), 사이트로 옮긴다

## 갈아탈 신호
- 노션이 반나절 넘게 늦어서 조원이 헷갈린 일이 3번을 넘으면 → A
- 신이 하루 종일 자리를 비우는 날이 생기면 → A (그날만이라도 다른 조원 노트북으로 B 를 돌리려면 그 사람을 노션 멤버로 올려야 해서 유료)
- 노션 말고 우리 화면이 필요해지면 (D26 앱과 합치기 등) → C
