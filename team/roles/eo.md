# 어 (디자인) — 시연, PR 리뷰, 페르소나

조가 한 일을 3분으로 보여 주고, 개발 아닌 눈으로 PR을 읽는 사람.
우리 조엔 마케팅이 없어서, 워크북의 마케팅 몫(페르소나, 출시 공지)도 맡는다.

## 순서
1. Lv1 연결 확인
2. (#12) 열린 PR 리뷰 댓글 (개발 아닌 1명)
3. (#13) 타깃 페르소나 1명 + 출시 공지 초안을 `team/docs/persona.md` 로 PR (노션 "직군 문서"에는 신이 옮긴다. 조원은 노션 게스트라 보기만)
4. (#11) 17:30까지 시연 대본, 18:00 시연
5. 하루 끝 스탠드업

## 시연 3분
| 시간 | 보여 줄 것 |
| --- | --- |
| 0:00 | `.mcp.json` (notion, team. 깃허브 토큰 없음), `claude mcp list` |
| 0:30 | 세션을 열면 "누구세요?" → whoami → 내 할 일이 바로 나오는 장면, progress |
| 1:15 | 회의록 → 이슈 → 직군별 결과 (PR, 노션) |
| 2:00 | 노션 허브: 진행률, 진행판, 스탠드업 (깃허브 댓글 → 신 노트북 서기 → 노션) |
| 2:30 | 테스트 3번, 일부러 만들지 않은 도구와 열지 않은 권한 (`team/docs/mcp-design.md`) |

시연 전 확인: 토큰, 비공개 노션, 개인 메일이 화면에 없는지.

## 바로 쓸 말
PR 리뷰:
```
team link_status 로 리뷰 기다리는 PR 을 찾고, 그 PR 의 바뀐 점 3줄, 확인할 점 2개 댓글 초안을 보여 줘. 댓글은 내가 깃허브 화면에 붙인다.
```
페르소나:
```
team 의 search_docs 로 "타깃" 을 찾고, 회의록과 README 를 보고 페르소나 1명 + 출시 공지 초안(200자, 과장 없이)을
team/docs/persona.md 로 써 줘. 브랜치 eo/docs-persona 에서 커밋, 푸시하고 team github_link 로 PR 만들기 링크 줘. 먼저 보여 줘.
```
