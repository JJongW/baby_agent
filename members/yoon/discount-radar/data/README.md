## 쓸 때 주의할 값

데이터를 해석하는 기준(추천 · 경고 등)은 정하지 않았다. 아래는 쓰는 쪽이 알아야 할 데이터의 특성이다.

| 특성 | 개수 | 주의 |
|---|---|---|
| 할인율 90% 이상 | 15 | 조건부 가격(제휴 · 묶음 등)이거나 데이터 오류일 수 있다 |
| 리뷰 0개 | 10 | `긍정%` · `리뷰등급`이 빈칸이다. 평가를 알 수 없다 |
| 리뷰 1~49개 | 10 | 긍정 %가 몇 명의 평가로 크게 흔들린다 |
| 긍정 70% 미만 | 24 | 평가가 좋지 않은 게임이다 |

## 데이터 편향 — 이 데이터로 말할 수 없는 것

- **Steam 세일 전체가 아니다.** 세일 중인 게임 약 18,000개 중 최대 500개(약 3%)다.
- **평가가 아주 좋은 게임에 치우쳐 있다.** `Reviews_DESC`는 "리뷰 많은 순"이 아니라 **긍정 % 높은 순**이다(첫 50개가 긍정 93~100%).
- **관련도순의 기준은 Steam이 공개하지 않는다.** Steam 세일 화면을 처음 열면 보이는 순서라는 것만 안다.
- **인기는 있지만 평가가 중간인 게임은 적게 들어 있다.** Steam 검색에 "리뷰 많은 순" 정렬이 없어서 이 층을 따로 모을 방법이 없었다.
- **하루치 스냅샷이다.** 할인은 이미 끝났을 수 있다. 할인 종료 시각은 이 경로에서 받을 수 없다.
- **최신 출시작은 거의 없다.** 최신순은 첫 50개 중 49개가 리뷰 0개라 수집 정렬에서 뺐다.

## 수집처 후보와 탈락 이유

확인일: 2026-11-06. robots.txt, 이용약관, API 문서 원문을 직접 열어 확인했다.

| 후보 | 종류 | robots.txt (가려는 경로) | 이용약관 | 결과 |
|---|---|---|---|---|
| Steam 스토어 (`/search/results/`, `/api/appdetails`) | 문서 없는 스토어 내부 API | 금지 아님 | 구독자 계약 4.C "봇 · 스크립트 금지". 스토어 웹 데이터까지 해당하는지 불분명 → 아래 "약관 4.C 판단" | **선택** |
| IsThereAnyDeal API | 공식 API (키 필요) | `/` 허용 | 데이터 변경 금지 · **경쟁 앱 금지** | **탈락** |
| SteamDB | 사이트 | `/deal/` · `/search/` 등 금지 | FAQ: "We also do not allow scraping/crawling on SteamDB." | **탈락** |

- **IsThereAnyDeal — 배포하면 "경쟁 앱 금지"에 걸린다.** 약관: "You MUST NOT make an app that could be considered a competition to IsThereAnyDeal or IsThereAnyDeal projects." 공개된 게임 할인 서비스는 ITAD와 같은 영역이다. 데이터는 가장 좋았지만(공식 API · 원화 · 역대 최저가 · 할인 종료 시각 · 여러 스토어), 약관을 끝까지 읽으니 우리 아이디어가 그 회사의 서비스였다.
- **SteamDB — 약관에서 크롤링을 명시적으로 금지한다.** 데이터가 필요하면 Steam에서 직접 가져가라고 안내한다.

## 약관 4.C 판단

> 윤, 2026-11-06 · 제출 전 윤이 다시 검수

- **판단:** 우리 수집은 스크립트를 쓰는 **자동화가 맞다.** 다만 4.C가 금지하는 대상인 "Content and Services"(1.B: Steam으로 내려받거나 접근하는 소프트웨어 · 콘텐츠 · 업데이트)에 스토어 웹 페이지와 가격 정보가 직접 들어 있지 않다고 해석하고, **위험을 감수하고 진행한다.**
- **판단 근거:** 4.C의 예시가 모두 계정을 쓰는 부정행위(계정 생성 · 통계 조작 · 보상 획득 · 신고 자동화)다. robots.txt가 우리가 쓰는 경로를 막지 않는다. 스토어 공개 데이터 수집이 널리 행해지는데도 이 경로가 막혀 있지 않아, 소량 수집의 실제 위험은 낮다고 본다.
- **수집 방식:** 한 번만 · 최대 510번 요청 · 1.5초 넘는 간격 · 봇이라고 밝힘 · 로그인하지 않음 · 거절하면 멈춤
- **공개 범위:** 사실 정보(이름 · 가격 · 리뷰 집계)만 담고 이미지 · 설명은 넣지 않는다. 전체 세일의 약 3%다. 데이터를 쓰는 화면은 원본 목록을 그대로 옮기지 않고 기준을 세워 가공해 보여 주는 것을 조건으로 한다(아래 "배포할 때 지킬 것" 6).
- **남는 위험:** Valve가 4.C를 더 넓게 해석할 수 있다. → **Valve나 퍼블리셔가 요청하면 데이터와 서비스를 바로 내린다.**
- **크롤링 검사 직원 판정:** 1차 고친 뒤 수집(약관 확인 필요 · 출처 없는 수치) → 이 판단을 기록한 뒤 2차 **수집해도 됨**
- **요청 한도:** appdetails 한도는 공식 문서가 없다. "5분에 약 200회"는 커뮤니티에서 알려진 수치이고 출처를 확인하지 못했다. 그래서 간격을 넉넉하게 잡았다.

## 배포할 때 지킬 것

> 화면은 별도로 만든다. 1 · 7번은 수집 쪽이, 2~6번은 이 데이터를 쓰는 화면 쪽이 지킨다.

1. **수집은 한 번만.** 화면은 Steam에 실시간으로 요청하지 않고, 저장한 CSV만 읽는다.
2. **출처 · 수집 시각을 표기한다.** "Steam 스토어 데이터 · 2026-11-06 수집"과 함께, 지금 가격과 다를 수 있다고 안내한다.
3. **Valve · Steam과 무관하다고 표기한다.** 제휴처럼 보이지 않게 한다.
4. **이미지는 넣지 않거나 Steam 주소로 링크만 건다.** 헤더 이미지는 퍼블리셔 저작물이라 레포에 저장하지 않는다.
5. **게임 링크는 Steam 스토어 페이지로 건다.** 실제 가격은 Steam에서 확인하게 한다.
6. **원본 목록을 그대로 옮기지 않는다.** 기준을 세워 가공한 결과(정렬 · 추천 · 판정 등)를 보여 준다. 기준은 화면을 만드는 쪽이 정한다. (데이터베이스 권리)
7. 403 · 429 · 리다이렉트를 받으면 바로 멈춘다.
