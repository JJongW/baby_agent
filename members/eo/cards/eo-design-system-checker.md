## 왜 만들었나
- 개발자가 화면을 구현할 때(Streamlit, CSS, 웹 컴포넌트 등) 디자이너가 정의한 규격 대신 임의의 하드코딩된 색상값(`#111111`), 비표준 여백(`margin: 13px`), 제각각인 폰트 크기와 버튼 형태가 자주 사용되었습니다.
- 화면이 출시(`/ship`)될 때마다 수동으로 스타일 코드를 일일이 확인하는 데 많은 시간이 걸리고 UI 통일감이 흐트러지는 문제가 있었습니다.

## 근거
- 워크북에서 요구하는 **"우리 화면에서 꼭 볼 5가지 원칙"**(컬러 토큰, 4/8px 스페이싱, 타이포그래피, 인터랙션 요소 규격, 빈 상태/에러 UI 대응)을 에이전트에게 맡김으로써 빠른 코드 리뷰가 가능합니다.
- 하드코딩된 값을 팀의 시맨틱 토큰으로 즉시 변환 제안하여 개발-디자인 간 커뮤니케이션 비용을 줄여줍니다.

## 어떻게 다루나
- **부르는 때**: 각 기능(F1~F5) 개발 및 화면 출시(`/ship`) 전후에 스타일 일관성을 검토할 때
- **부르는 말 예시**: "eo-design-system-checker로 app.py랑 style.css UI 일관성 봐줘"
- **넣는 것**: 검토할 CSS 파일, 스타일이 적용된 웹 코드(`app.py`, React 컴포넌트 등)
- **받는 것**: 5대 핵심 체크리스트 요약과 수정 권장 코드 리포트, 그리고 웹 접근성 검토 연계 안내
- **쓰는 도구**: 읽기 전용 (`ReadFile`, `Glob`, `Grep`)

## 한계와 주의 (kwon 접근성 에이전트와의 분담)
- 디자인 시스템에 없는 특별한 비주얼 효과나 커스텀 예외 케이스는 디자이너가 직접 확인해야 합니다.
- **역할 경계 분담**:
  - `eo-design-system-checker`: 디자인 토큰 일관성, 4/8px 여백 체계, 버튼/인풋 조형 규격
  - `kwon` 접근성 에이전트: WCAG 명도 대비(4.5:1), 스크린리더 라벨(`aria-*`), 키보드 포커스 링, 최소 터치 타겟(44px) 점검 (이 에이전트는 해당 항목을 kwon님 에이전트로 위임 안내합니다)
