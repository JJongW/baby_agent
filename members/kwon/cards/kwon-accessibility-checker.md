# kwon-accessibility-checker

- **직군**: 디자인
- **만든 날**: 2026-11-05

## 왜 만들었나
시안을 넘기기 전에 접근성을 확인하려면 WCAG 기준표를 열어 놓고 색 대비, 클릭 영역, 상태 표시를 하나씩 손으로 따져야 한다. 바쁘면 이 확인을 건너뛰게 되고, 개발 단계에서야 대비 부족이 발견된다.

## 근거
접근성 문제는 시안 단계에서 고치는 것이 개발 이후보다 훨씬 싸다. WCAG 2.1 A·AA는 점검 항목이 명확해서 에이전트가 같은 기준으로 반복 점검하기 좋다.

## 어떻게 다루나
- **부르는 때**: 시안을 넘기기 전, 또는 UI 컴포넌트를 만든 뒤
- **부르는 말 예시**: "kwon-accessibility-checker로 이 로그인 화면 봐줘"
- **넣는 것**: 시안 이미지 파일 경로, 또는 HTML/CSS 파일
- **받는 것**: 맨 위에 🔴 긴급 / 🟡 중요 / 🟢 개선으로 나눈 우선순위 표, 이어서 문제마다 ① 진단 요약 표(Pass/Fail/Warning, Level A/AA, WCAG 기준 번호·명칭) ② 원인 및 맥락 분석 ③ Before & After 개선안(기존 HEX vs 수정 HEX, 오류 마크업 vs ARIA 적용 마크업) ④ 스크린 리더/키보드 가상 시뮬레이션
- **쓰는 도구**: 읽기만 한다 (Read, Glob, Grep). 기능 코드를 포함해 파일을 직접 고치지 않고, 개선안은 답변 안의 제안으로만 준다

## 한계와 주의
이미지만 보고는 정확한 대비 수치를 알 수 없어 추정이 섞인다. 스크린 리더와 키보드 이동은 실제 조작으로만 확인되므로 "구현에서 확인 필요"로 남긴다. 최종 판단은 사람이 한다.
