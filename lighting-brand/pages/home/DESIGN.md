# ONDO 디자인 규칙 (시안)

> 상태: **시안 v3**. 상경(어)이 만든 안이다. 지영(권)과 상의하기 전이다.
> 범위: 1차 배포 전에 꼭 정할 다섯 가지(색, 글꼴, 여백, 사진 쓰는 법, 키보드 초점 표시)를 모두 담았다. 사진 자체(빛, 톤, 장면, 파일)는 사진 담당이 [`images/README.md`](../../images/README.md)에서 관리한다. 나머지는 맨 아래 "다음에 정할 것"에 적었다.
> **페이지와 섹션 레이아웃은 정하지 않는다.** 섹션마다 구성이 달라서 배치와 열 수는 각자 정하고, 그 안에서 아래 값(색, 글꼴, 여백 단계)만 쓴다.
> 다섯 페이지 모두 이 규칙을 따른다. 페이지 안 `<style>`에서도 새 색이나 새 값을 만들지 않고 아래 토큰만 쓴다.

## 정하는 방법

1. **안 만들기**: 디자인 담당 상경(어)과 지영(권)이 함께 상의해 값을 정한다
2. **팀 상의**: 정한 안을 팀원 다섯 명 모두(신, 정연, 지혜 포함)에게 보여 주고 의견을 받는다
3. **확정**: 팀 상의를 거친 뒤 확정한다. 확정된 값은 신(PO)에게 `common/style.css` 반영을 요청한다

표의 **결정** 칸은 단계에 따라 이렇게 적는다.
- 비어 있음: 아직 안 정함 (지금 적힌 값은 상경의 제안)
- `안: 값`: 상경·지영이 정한 안. 팀 상의 전
- `확정: 값`: 팀 상의를 거쳐 확정

## 0. 방향

**한 줄:** 어두운 방에 한지 등 하나가 켜져 있는 순간처럼, 고요하고 따뜻하게.

- **와비사비**: 완벽하지 않은 것, 손으로 만든 결, 시간이 남긴 흔적(구겨지고 바랜 한지)을 아름답게 본다
- **덜어내는 디자인**: 더할 것보다 뺄 것을 먼저 찾는다. 장식, 그림자, 테두리, 색, 문구를 줄이고 빈 곳을 넉넉히 둔다
- **사진과 빛이 주인공**: 화면에서 가장 밝고 따뜻한 것은 조명 사진이다. 화면 요소(글자, 버튼, 선)는 그 뒤로 물러난다
- **이미지 중심, 글은 최소**: 글보다 사진이 먼저 눈에 들어오게 한다
- 피하는 것: 반짝이는 광택, 그림자, 그라데이션 장식, 둥근 알약 모양 버튼, 채도 높은 색, 꽉 찬 화면, 느낌표와 과장된 문구

### 레퍼런스에서 확인한 것

2026-11-11에 브라우저로 세 사이트를 열어 화면에 실제로 쓰인 값을 읽었다.

| | [Akari 판매 페이지](https://shop.noguchi.org/collections/akari-light-sculptures) | [Aesop](https://kr.aesop.com/) | [APFR](https://apfr.jp/en) |
| --- | --- | --- | --- |
| 바탕 | `#F7F4EF` 미색 | `#FFFEF2` 노란 기운 미색 | `#EEE4D4` 베이지 |
| 구역 바탕 | `#EDE8E3` | `#EFE8D8` | (바탕과 같음) |
| 본문 글자 | `#000000` 검정 | `#333333` 짙은 회색 | 검정 78% (바탕 위 약 `#34322F`) |
| 보조 글자 | `#6C6C6C` | `#666666` | 검정 49% (약 `#79746C`) |
| 선 | `#E4DBCC` 따뜻한 베이지 | 짙은 회색 20% | 거의 안 씀 |
| 강조색 | 없음 | `#945C26` 갈색 (작은 글자 한 곳) | 없음 |
| 어두운 면 | `#3D3D3C` | `#333333` (버튼) | 첫 화면 사진이 어두운 초콜릿 갈색 |
| 제목 글꼴 | 세리프 (Times 계열) | 산세리프 하나만 | 산세리프 |
| 메뉴 | 작은 영어 대문자, 자간 넓게 | 14px 한글 | 12px 좁은 영어 대문자, 자간 넓게 |

**알게 된 것**
1. **바탕은 셋 다 따뜻한 미색이나 베이지다.** 순수한 흰색(`#FFFFFF`)은 쓰지 않는다
2. **글자는 검정 또는 짙은 회색 하나와 보조 회색 하나뿐이다.** 글자색을 늘리지 않는다
3. **강조색은 거의 없다.** Aesop만 갈색을 작은 글자 한 곳에 쓴다
4. **따뜻하고 흙 같은 느낌은 화면 색이 아니라 사진에서 나온다.** Akari는 모든 제품을 물 빠진 갈색(테라코타 느낌) 배경 앞에서 찍었고, APFR은 어두운 갈색 사진 한 장으로 첫 화면을 채운다. 화면 요소는 무채색에 가깝게 물러나 있다

→ ONDO도 **화면은 한지 미색과 먹색으로 조용하게, 흙·테라코타·마른 대나무의 느낌은 사진 배경과 넓은 구역 바탕으로** 낸다.

## 1. 색 ✅ 1차 필수

**분위기:** 채도가 낮고 물이 빠진 듯한, 자연 재료(한지, 마른 대나무, 흙)의 따뜻한 색. 특정 색 하나를 고집하지 않고 이 분위기 안에서 고른다.

### 토큰 (6개)

| 토큰 | 제안 값 | 이름 뜻 | 쓰는 곳 | 근거 | 결정 |
| --- | --- | --- | --- | --- | --- |
| `--hanji` | `#FBF9F4` | 한지 흰색 | 바탕 (화면의 대부분) | Akari `#F7F4EF`와 Aesop `#FFFEF2` 사이. `--hanji-deep`과 명도 차이가 또렷하게 밝게 | |
| `--hanji-deep` | `#ECE5D8` | 마른 대나무빛 한지 | 사진 자리, 카드 바탕, 구역 나눔 바탕 | Akari `#EDE8E3`, Aesop `#EFE8D8`, APFR `#EEE4D4` 사이 | |
| `--ink` | `#24201D` | 먹색 (갈색 기운) | 제목, 본문, 버튼 | 셋 다 검정~짙은 회색. 바탕에 맞춰 따뜻하게 | |
| `--ink-soft` | `#69625A` | 옅은 먹색 | 보조 글자, 캡션, 제품 정보, 입력칸 테두리 | Akari `#6C6C6C`, Aesop `#666666` | |
| `--line` | `#E2D9CA` | 선 | 구분선 (장식용) | Akari `#E4DBCC` | |
| `--earth` | `#8A5A3C` | 물 빠진 흙 | 유일한 강조색. 한 화면에 한 곳만 | Aesop `#945C26`보다 채도를 낮춤 | |

바탕 2 + 글자 2 + 선 1 + 강조 1. Akari(5개)에 흙빛 강조색 하나를 더한 정도로 덜어냈다.

**뺀 것과 이유**
- `--night`(밤), `--glow`(불빛): 조명 켜기·끄기는 제품 사진 한 쌍(켜짐, 꺼짐)으로 낸다. 사진이 아직 없는 제품의 CSS 대체 효과는 제품 페이지 안의 일이라 정연과 따로 정한다
- `--line-strong`(진한 선): 입력칸 테두리는 `--ink-soft`(대비 5.71)로 충분하다

지금 `common/style.css`와 바꾸는 표 (신에게 요청할 때 같이 보낸다)

| 지금 | 바뀔 것 |
| --- | --- |
| `--paper` `#f7f4ee` | `--hanji` `#FBF9F4` (이름과 값) |
| `--paper-deep` `#ece6da` | `--hanji-deep` `#ECE5D8` (이름과 값) |
| `--ink` `#1d1b18` | `#24201D` (값만) |
| `--ink-soft` `#6b655c` | `#69625A` (값만) |
| `--line` `#d9d2c4` | `#E2D9CA` (값만) |
| `--glow` `#e8b45a` | 뺌 |
| (없음) | `--earth` 새로 추가 |

### 색 비율

| 색 | 비율 | 메모 |
| --- | --- | --- |
| 한지 (`--hanji`, `--hanji-deep`) | 80% 이상 | 바탕. 비워 두는 곳 |
| 먹 (`--ink`, `--ink-soft`) | 15% 안팎 | 글자, 버튼 |
| 흙 (`--earth`) | 아주 조금 | 한 화면에 한 곳 |

### 대비 (WCAG AA: 본문 글자 4.5 이상, 꼭 보여야 하는 선 3 이상)

| 색 | `--hanji` 위 | `--hanji-deep` 위 | 쓸 수 있는 곳 |
| --- | --- | --- | --- |
| `--ink` | 15.36 | 12.90 | 모든 글자 |
| `--ink-soft` | 5.71 | 4.80 | 모든 글자, 입력칸 테두리 |
| `--earth` | 5.53 | 4.65 | 모든 글자 |
| `--line` | 1.33 | 1.12 | **글자 안 됨.** 장식 선만 |

### 쓰는 규칙
- 글자색은 `--ink`, `--ink-soft`, `--earth` 세 가지만 쓴다. 사진 위에서는 `--hanji` 하나만
- `--earth`는 한 화면에 한 곳만 쓴다
- 흙, 테라코타, 마른 대나무의 따뜻한 느낌은 사진이 맡는다. 화면 요소에 색을 더하지 않는다

## 2. 글꼴 ✅ 1차 필수

### 두 글꼴의 역할

| 글꼴 | 쓰는 곳 | 이유 |
| --- | --- | --- |
| **마루 부리** (`MaruBuri`, 네이버, 바탕체) | 브랜드명(로고), 큰 제목(`h1`), 섹션 제목(`h2`), 머리 메뉴 | 붓으로 쓴 듯한 획이 한지·손맛과 맞는다. 화면의 얼굴이 되는 글자에만 쓴다 |
| **IBM Plex Sans KR** (고딕) | 설명문, 본문, `h3` 이하, 캡션, 버튼, 제품 정보, 작은 표시 글자(`.eyebrow`) | 획 끝이 살짝 각진 담백한 고딕이라 마루 부리 옆에서 단정하게 물러난다. 영문은 IBM Plex Sans와 같은 모양이라 제품 코드(T-01)와 영어 표시 글자가 잘 어울린다 |

| 토큰 | 제안 값 | 결정 |
| --- | --- | --- |
| `--font-title` | `"MaruBuri", "Noto Serif KR", serif` | |
| `--font` (본문) | `"IBM Plex Sans KR", "IBM Plex Sans", -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif` (지금은 Pretendard) | |

마루 부리는 무료이고 웹사이트 탑재가 허용된다 (네이버 나눔글꼴 라이선스, [눈누](https://noonnu.cc/font_page/487)).
IBM Plex Sans KR도 무료다 (SIL Open Font License, Google Fonts). 한글이 들어 있는 것은 `IBM Plex Sans KR`이다. 이름에 KR이 없는 `IBM Plex Sans`에는 한글이 없으니 꼭 KR을 쓴다.

### IBM Plex Sans KR 불러오는 코드 (신에게 요청용)

지금 `common/style.css` 맨 위의 Pretendard `@import`를 아래로 바꾼다. 쓰는 굵기 400·500만 불러온다.

```css
@import url("https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+KR:wght@400;500&display=swap");
```

### 마루 부리 불러오는 코드 (신에게 `common/style.css` 반영 요청용)

눈누에 있는 코드는 굵기 값이 몇 군데 잘못 적혀 있어서(여러 파일이 모두 400으로 적힘) 아래처럼 고쳐 쓴다. 쓰는 굵기 세 가지만 불러와 페이지를 가볍게 한다.

```css
@font-face {
  font-family: "MaruBuri";
  src: url("https://hangeul.pstatic.net/hangeul_static/webfont/MaruBuri/MaruBuri-Light.woff2") format("woff2");
  font-weight: 300; font-display: swap;
}
@font-face {
  font-family: "MaruBuri";
  src: url("https://hangeul.pstatic.net/hangeul_static/webfont/MaruBuri/MaruBuri-Regular.woff2") format("woff2");
  font-weight: 400; font-display: swap;
}
@font-face {
  font-family: "MaruBuri";
  src: url("https://hangeul.pstatic.net/hangeul_static/webfont/MaruBuri/MaruBuri-SemiBold.woff2") format("woff2");
  font-weight: 600; font-display: swap;
}
```

### 글자 크기와 굵기

| 토큰 | 쓰는 곳 | 글꼴 | 크기 | 굵기 | 줄 간격 | 자간 | 결정 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `--title-xl` | 첫 화면 큰 제목 (`h1`) | 마루 부리 | `clamp(32px, 5vw, 52px)` | 300 | 1.4 | -0.03em | |
| `--title-lg` | 섹션 제목 (`h2`) | 마루 부리 | `clamp(24px, 3vw, 32px)` | 400 | 1.45 | -0.03em | |
| (로고) | 브랜드명 ONDO | 마루 부리 | 20px | 600 | 1 | 0.16em | |
| (메뉴) | 머리 메뉴 | 마루 부리 | 15px | 400 | 1 | 0.04em | |
| `--text-lg` | `h3`, 인용문 | IBM Plex Sans KR | 18px | 500 | 1.6 | -0.01em | |
| `--text-md` | 본문, 설명문 | IBM Plex Sans KR | 16px | 400 | 1.8 | -0.01em | |
| `--text-sm` | 캡션, 제품 정보, 버튼, 바닥 | IBM Plex Sans KR | 14px | 400 | 1.7 | 0 | |
| `--text-xs` | 작은 표시 글자 (`.eyebrow`) | IBM Plex Sans KR | 12px | 500 | 1.5 | 0.08em | |

### 쓰는 규칙
- 마루 부리는 위 표의 네 곳(로고, `h1`, `h2`, 메뉴)에만 쓴다. 본문이나 버튼에 쓰지 않는다
- 굵기는 마루 부리 300·400·600, IBM Plex Sans KR 400·500만 쓴다. 굵은 글자로 강조하지 않고 크기와 여백으로 위계를 만든다
- 한 문단은 16px 이상으로 쓴다. 14px 이하는 캡션, 제품 정보처럼 짧은 글에만
- 영어 대문자 표시(`.eyebrow`)는 한 화면에 섹션마다 하나만

## 3. 여백과 폭 ✅ 1차 필수

여백은 넉넉하게 둔다. 고민되면 더 비운다.

### 간격 단계 (8의 배수)

| 토큰 | 값 | 쓰는 곳 | 결정 |
| --- | --- | --- | --- |
| `--space-1` | 8px | 아이콘과 글자 사이, 이름과 가격 사이 | |
| `--space-2` | 16px | 문단 사이, 카드 안 사진과 글 사이 | |
| `--space-3` | 24px | 카드 사이(가로), 제목과 본문 사이 | |
| `--space-4` | 40px | 카드 줄 사이(세로), 덩어리 사이 | |
| `--space-5` | 64px | 섹션 안 큰 덩어리 사이 | |

이 다섯 개 말고 20px, 28px 같은 값을 새로 쓰지 않는다.

## 4. 사진 쓰는 법 ✅ 1차 필수

사진 자체(빛, 톤, 장면, 파일 크기, 이름, 출처)는 사진 담당이 [`images/README.md`](../../images/README.md)에서 관리한다. 사진은 계속 추가되는 중이다.
여기에는 다섯 명이 **페이지에 사진을 놓을 때** 똑같이 맞출 것만 적는다.

### 화면 비율

| 쓰는 곳 | 비율 | 결정 |
| --- | --- | --- |
| 홈 첫 화면 | 16:9 (휴대폰에서는 4:5로 잘라 조명이 보이게) | |
| 제품 카드 | 4:5 | |
| 본문 사이 사진 (스토리, 매거진) | 3:2 | |


### 사진 주변
- 사진과 사진 사이, 사진과 글 사이는 `--space-4` 이상 띄운다
- 사진에 테두리, 모서리 둥글림, 그림자를 넣지 않는다

### 사진 위 글자
- 사진의 어두운 쪽에 `--hanji` 글자를 올린다. 사진에 색 막을 덮지 않는다
- 제목 한 줄 + 설명 한 줄 + 버튼 하나까지만

### 캡션
- 사진 아래 `--text-sm`, `--ink-soft`, 한 줄. 예: "한지를 한 장씩 붙이는 과정."

### 사진이 아직 없을 때
- 같은 비율의 자리(`.ph`)를 `--hanji-deep` 바탕으로 두고, 가운데 "사진 준비 중"을 `--text-sm`, `--ink-soft`로 쓴다

### 대체 글
- 사진마다 `alt`에 무엇이 보이는지 한 문장으로 쓴다. 예: "어두운 방, 나무 탁자 위에서 빛나는 한지 테이블 등"

## 5. 키보드 초점 표시 ✅ 1차 필수

마우스 없이 Tab 키로 움직이는 사람이 지금 어디에 있는지 보이게 한다. 지금 `style.css`에는 이 모양이 없다.

| 상황 | 제안 모양 | 결정 |
| --- | --- | --- |
| 밝은 바탕 (`--hanji`) | `outline: 1px solid var(--ink); outline-offset: 4px;` | |
| 사진 위 (첫 화면 버튼 등) | `outline: 1px solid var(--hanji); outline-offset: 4px;` | |

```css
:focus-visible { outline: 1px solid var(--ink); outline-offset: 4px; }
.is-dark :focus-visible { outline-color: var(--hanji); }
:focus:not(:focus-visible) { outline: none; }
```

### 쓰는 규칙
- `:focus-visible`을 써서 키보드로 움직일 때만 보이게 한다. 마우스로 누를 때는 안 보인다
- 초점 표시를 지우지 않는다 (`outline: none`만 단독으로 쓰지 않는다)
- 버튼, 링크, 메뉴, 입력칸, FAQ 질문, 켜기·끄기 버튼 모두 Tab으로 갈 수 있어야 한다
- 휴대폰에서 누르는 영역은 가로세로 44px 이상
