# 조명 브랜드 페이지: Claude가 먼저 지킬 것

이 폴더는 가상 한지 조명 브랜드 "온도(ONDO)"의 소개 사이트다. 페이지 다섯 개를 다섯 명이 하나씩 맡는다.
기획은 [PRD.md](PRD.md), 폴더 지도와 배포는 [README.md](README.md).

## 작업을 시작할 때 (매번, 첫 답에서)
1. 최신 main을 받았는지 확인한다. 안 받았으면 사용자에게 알리고 받는다: `git switch main && git pull origin main`
2. 사용자에게 이렇게 말하고 묻는다. 답을 듣기 전에는 파일을 고치지 않는다.
   > 조명 브랜드 페이지 제작을 시작합니다. 본인은 누구신가요?
   > 상경(홈), 정연(제품), 신(FAQ), 지혜(스토리), 지영(매거진)
3. 답을 들으면 아래 표에서 그 사람의 페이지 폴더를 정하고, 그 폴더의 `CLAUDE.md`를 읽는다
4. 그 사람 이름으로 브랜치를 만든다: `<레포 폴더 이름>/feat-lighting-<페이지>` (예: `yoon/feat-lighting-product`)

| 사람 | 페이지 | 고쳐도 되는 폴더 | 레포 폴더 이름 (브랜치 앞) |
| --- | --- | --- | --- |
| 상경 | 홈 | `pages/home/` | `eo` |
| 정연 | 제품 | `pages/product/` | `yoon` |
| 신 | FAQ | `pages/faq/` | `shin` |
| 지혜 | 스토리 | `pages/story/` | `jihye` (깃허브 `Jihye-kr`) |
| 지영 | 매거진 | `pages/magazine/` | `kwon` |

## 다른 건 건드리지 않는다
- 고치는 곳은 **그 사람의 페이지 폴더 하나뿐**이다. 다른 페이지 폴더, `common/`, `PRD.md`, `README.md`, 이 파일, 레포의 다른 폴더(`discount-radar/`, `members/` 등)는 고치지 않는다
- `common/`(색, 글꼴, 메뉴, 제품 데이터)을 바꿔야 할 것 같으면 고치지 말고, 무엇을 왜 바꾸고 싶은지 정리해 사용자에게 "신(PO)에게 요청하세요"라고 안내한다
  - 예외: 제품 데이터 `common/products.js`는 정연(제품)이 고친다
- 철학은 **와비사비**: 완벽하지 않은 것, 손으로 만든 결, 시간이 남긴 흔적을 아름답게 본다. 반짝이는 광택, 강한 대비, 꽉 찬 화면은 피한다
- 디자인 방향은 **일본의 덜어내는 디자인**이다. 더할 것보다 뺄 것을 먼저 찾는다: 장식, 그림자, 테두리, 색, 문구를 줄이고 빈 곳을 넉넉히 둔다
- 디자인 값(색, 글꼴, 여백, 사진 비율, 초점 표시)은 상경(어)의 [디자인 규칙](pages/home/DESIGN.md)을 따른다. 새 색을 만들지 말고 `common/style.css`의 `var(--...)` 값만 쓴다

## 만들 때 지킬 것
- 정적 사이트다: HTML, CSS, 조금의 JavaScript. 빌드 도구나 프레임워크를 들이지 않는다
- 각 페이지 `index.html`의 `<header data-site-header>`, `<footer data-site-footer>`, 맨 아래 `<script>` 두 줄은 지우지 않는다
- 사진: Noguchi, Akari 등 실제 브랜드의 사진, 이름, 글을 쓰지 않는다. AI로 만든 이미지나 무료 사진만, 출처를 `showcase.md`에 적는다. 한 장 300KB 이하
  - 예외: 스토리 페이지(`pages/story/`)는 참고한 실제 브랜드의 기록 사진을 쓸 수 있다. 대신 그 페이지 바닥(footer)에 사진 출처를 꼭 적고, `showcase.md`에도 적는다. 사진은 `pages/story/images/`에 둔다
- 휴대폰 폭(375px)에서 옆으로 밀리지 않게 한다. 버튼과 링크는 키보드로도 쓸 수 있게 한다

## 다 됐다고 말하기 전에
1. `cd lighting-brand && python3 -m http.server 3320` 으로 띄워 내 페이지를 열어 본다 (데스크톱, 휴대폰 폭)
2. 레포 맨 위에서 `bash scripts/check.sh`
3. 내 페이지 폴더의 `showcase.md`(작품 게시)를 채운다
4. PR 설명에 내가 고친 파일이 내 페이지 폴더 안뿐인지 적는다
